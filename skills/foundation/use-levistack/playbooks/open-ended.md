# Playbook: open-ended

Matches "figure it out", a large migration, an ambitious change across many parts, or work a person reviews after stepping away. Use it when no narrower playbook fits.

| Step | Do | Skill |
|---|---|---|
| 1 Restate | Say the goal, what done looks like as a check that can fail, and the scope, before designing the run | — |
| 2 Design the run | Frame done, size the scope, set the rigor, then write the phase list a person can review | `figure-it-out` |
| 3 Run | Each phase uses the playbook that fits it: `feature`, `bug-fix`, `refactor`, `design-shape`, or `parallel` | the phase's playbook |
| 4 Log | One row per decision as it lands: what, why, evidence, result | `handoff` (Write, decision log) |
| 5 Prove | Check the whole against the done check on the real product | `verify` |

Stop for a yes before a multi-hour run, and before any outward or destructive step.

**Reply:** the phase list, the rigor level and why, the decision log path, what is proven against the done check, and what is still open.
