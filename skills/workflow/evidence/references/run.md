# Run or plan a task

Use this procedure for an explicit evidence task. In **Plan** mode, finish after step 4 and do not edit files or send messages.

1. Classify the request as a question, a task, or a plan request. Extract decisions the user already made. A question asks for findings and stays read-only unless the user also asked for a change.
2. Name the deliverable, quantity when relevant, intended reader, destination, and an observation that would prove it. Record material constraints and the files or systems in scope. Verify a named path or tool before relying on it. Check a simple assumption instead of asking the user to confirm it.
3. Enumerate available sources before reading deeply. Read the applicable project instructions, the actual implementation or records, and the task-specific skill. Separate current behavior, tests, proposals, and memory. If the sources disagree, report the conflict and decide which record governs the target version before changing behavior.
4. Choose one approach and write a short checklist for multi-step work. Identify the exact check for each consequential item. For a requested plan, deliver this checklist with evidence and stop here.
5. Make the smallest authorized change. Revisit the source when a field, API, number, or policy is uncertain. Use parallel readers only for independent questions and pass each a bounded output. Keep edits and final judgment with the owner of the task.
6. Run `verify` against the finished result and the relevant surrounding checks. For a consequential change, use `second-opinion` if an independent reviewer is available. Treat their result as a finding to verify, not proof by itself. If a check fails, fix the cause and rerun; report an external blocker rather than calling the task complete.
7. Report the outcome first. Name the changed artifact, actual checks, unresolved facts, and any requested action that still needs authorization. Do not claim to have run a service, published a result, or checked a source that was unavailable.

For a one-line, single-file edit with an obvious check, make the edit, run that check, and report it without the full checklist. For a large task, keep the checklist in a local work note so no item disappears.
