# Frame a goal for a later session

Use Goal mode only when the user asks for a reusable prompt or goal brief. If they ask for the deliverable now, switch to Run and make it.

1. Extract the intended artifact, quantity, audience, quality bar, destination, named resources, and any permission limits from the user's words and the workspace. Mark an unstated item as an assumption only if it changes the result.
2. Check every path, tool, asset, and service that the prompt will name. Use a verified resource only when it is needed; give the later session a discovery instruction for the rest. Do not invent audience size, urgency, credentials, or approval.
3. Define completion as observations on the finished medium: execute a CLI on representative and bad input, load and use a page, inspect a rendered document, or reproduce a calculation. Choose the number of passes from the risk and scope; never make a fixed pass count a substitute for an actual check.
4. Write a short prompt in the user's voice. State the outcome and constraints, allow implementation choices within that scope, require the medium-specific checks, and name the handoff artifact. Preserve the user's authorization boundary for publication, deployment, external messages, and destructive actions.
5. Read the prompt as a fresh agent would. Remove phantom resources, hidden dependencies, vague "done" claims, and steps that prescribe more than the goal requires. Return the prompt and only the material assumptions.

The prompt is the deliverable in this mode. Do not claim that its requested work has already been done.
