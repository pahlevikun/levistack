# Structured content artifact

Use a `structured-content.md` file when the topic is long, multi-section, or will feed both vector layout and optional raster drafts. It sits between source analysis and visual build.

Template: [../templates/structured-content.md](../templates/structured-content.md). Folder layout: [project artifacts](project-artifacts.md).

## Rules

- Markdown only in this file.
- Do not add facts that are not in the source or evidence ledger.
- Copy statistics, quotes, and labels exactly. Fix typos only when the source is clearly wrong and you note the fix.
- Strip secrets, tokens, and private paths before writing.
- State learning goals or reader outcomes at the top when the piece is educational.
- Each section lists: headline, body text (verbatim where factual), visual idea, and on-canvas labels.

## Workflow step

1. Finish [evidence](evidence.md) notes or a short `analysis.md` if the source is messy.
2. Fill `structured-content.md` from the template.
3. Pick layout and mood via [layout mood catalog](layout-mood-catalog.md) or [layout types](layout-types.md).
4. Run [confirmation gates](confirmation-gates.md) before raster drafts.
5. For vector delivery, translate sections into [design specification](../templates/design-specification.md) slots and composition panels.

## Language

If source language differs from delivery language, confirm target language before raster generation. Vector builds can keep bilingual labels when the brief asks for it.
