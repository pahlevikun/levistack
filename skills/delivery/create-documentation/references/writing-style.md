# Technical writing across document types

## Establish the reader and the evidence

1. Name the reader, the task, and the document's boundary. Infer these from the request and local documents before asking.
2. Read the existing owner of the topic. Extend it instead of creating another maintained copy.
3. Keep a working list of important claims with their source locations and checked revision. The client document need not expose private repository paths.
4. Separate current behavior, required contract, historical record, and proposed change. When implementation and contract disagree, report the disagreement instead of silently choosing one.
5. Distinguish implemented, deployed, and externally verified. A passing unit test establishes none of the deployment facts.

## Make the document usable

- Lead with the result or decision the reader needs. Define unfamiliar terms before relying on them.
- Use exact domain terms, field names, units, commands, and paths. Choose one name per concept.
- Put conditions before instructions. Give an action and its observable result in a procedure.
- Use tables for comparable facts and lists for ordered work. Add a diagram only when relationships are easier to understand visually.
- Separate lookup material from teaching and rationale. A package can contain all three under clear headings.
- Preserve an existing document's language and useful structure when editing. Change the passages needed to fix a named problem.

## Check before handoff

Read the finished document as a reader without author context. Check that terms, links, examples, and cross-references resolve. Compare completeness claims with a real inventory rather than a count from memory.

Label a sample as illustrative, fixture-tested, schema-checked, or live-tested according to what happened. Record the environment and date where useful. Unknown values stay unknown. Estimates and inferred causal claims say how they were obtained.

Keep accepted incident records, release entries, and decisions traceable. Add a correction or superseding record according to local policy rather than silently rewriting history.
